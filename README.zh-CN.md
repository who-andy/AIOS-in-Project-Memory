# AIOS in Project Memory

**让 AI 在本地项目目录里自己创建长期记忆文件、持续记录进度，并在新对话或更换 AI 后快速恢复记忆，接着上次继续。**

你只需要正常聊天、学习或开发。AI 会自行判断哪些信息值得保存、该建什么文件、如何维护。**不用自己设计文件结构，也不用每次开启新 Session 都从头解释项目。**

## 一键安装

```bash
npx skills add who-andy/AIOS-in-Project-Memory
```

全局安装，供多个项目使用：

```bash
npx skills add who-andy/AIOS-in-Project-Memory -g
```

查看 CLI 是否识别到该 Skill：

```bash
npx skills add who-andy/AIOS-in-Project-Memory --list
```

安装使用开源 [Skills CLI](https://github.com/vercel-labs/skills)，需要 Node.js/npm 和兼容的 AI Agent。

## 它是怎么工作的？

1. **正常和 AI 聊天。** 先讨论项目想做什么、如何学习、软件要实现哪些功能。可以聊清楚后再正式启动记忆系统。
2. **AI 自动创建记忆文件。** 正式初始化时，AI 根据目前已有的讨论和资料，在**本地项目目录**自行建立入口规则、进度记录以及必要的其他文件。具体结构由 AI 决定。
3. **聊天过程中持续保存。** AI 通过生成的项目规则，在后续工作时及时记录重要决策、学习进度、错误、纠正和下一步。
4. **开启新对话，甚至更换 AI。** 只要新的 Agent 可以访问相同的项目目录并读取入口规则，它就能恢复相关记忆，从之前的进度继续。

例如，学习了几周之后，项目目录可能包含简短的入口说明、学习进度和详细笔记。但**这些文件由 AI 根据实际项目设计**，Skill 不会强制套用某种模板。

## 怎么开始？

**方式一：先讨论，准备好了再初始化**

> 我们已经讨论得差不多了。请使用 aios-in-project-memory，在当前本地项目目录中建立长期记忆系统。你自己决定需要哪些文件，以后持续维护。

**方式二：讨论期间就保存信息**

> 使用 aios-in-project-memory，一边和我讨论一边把有价值的信息记录到当前项目目录。暂时不用建立完整结构，等我说正式开始再初始化。

**方式三：已经学习或开发到一半**

> 这个项目我已经做了很久，之前还有好几个对话。请使用 aios-in-project-memory，从你实际能访问的旧对话和文件中恢复当前进度，在本地建立长期记忆，让我从现在的进度继续。

## 随着项目变化，自动调整复杂度

**只有一个目标，就保持简单。** AI 只创建当前真正需要的记忆记录；换一个聊天 Session，不会凭空多出一个子项目。

**以后出现多个目标，再按需扩展。** 比如大学申请逐渐涉及 PS、CV、活动素材。它们可以共享一套可信的背景事实，各自保留草稿、决策和进度。用户不用提前规划文件夹。

**目标完成或减少，还能再简化。** AI 可以归档已完成的任务，合并重复的活跃记录，减少新 Session 必须读取的内容；历史仍应可恢复。暂时没提某件事，不代表用户放弃它。更新共享事实也不会擅自改写其他文书。

整个原则是：**始终使用足以正确恢复项目进度的最简单结构。**

## 多个目标自动分目录，防止记忆串用

一个项目只有一个目标时仍然保持极简。但**出现多个要求不同的独立目标**时，AIOS 必须为这些目标建立各自的目录，分别保存要求、草稿和进度。跨目标共用的真实素材另外集中管理。

例如同一个申请 Project 中，港大和港科的 PS 可以共享活动经历，但港大的专业要求、写作限制和草稿决定不能直接当成港科的要求。每次开始任务，AI 都需要确认当前目标；不明确时先问清楚。

示例结构（由 AI 根据实际项目调整，并非固定模板）：

```text
项目/
├── AGENTS.md     # 宿主需要时创建的入口
├── shared/       # 共用事实和活动素材
├── hku/          # 港大专属要求、草稿、进度
└── hkust/        # 港科专属要求、草稿、进度
```

如果以前所有文件都放在根目录，**更新 Skill 并不会自动搬动旧文件**。请在原项目目录要求 AIOS 检查旧文件的归属、备份、分类迁移、修复链接，并复查已有草稿是否串用了其他目标的要求。对归属不确定的内容应暂缓分类，不要猜测。

## 具体会保存什么？

AI 会尽量保存**能够帮助下一次对话准确继续**的重要内容，例如项目目标、当前进度、已验证成果、重要决策及原因、学习中的错误与纠正、待解决问题和下一步。

新 Session 优先读取精简的当前状态，需要时再检索详细历史，避免每次塞入整段旧聊天。对于尚未确认的想法，AI 应明确标注，避免把讨论中的猜测误记为最终决定。

项目已经进行到一半也可以使用。它支持从可访问的旧资料中逐步恢复历史，之后继续补录。

## 曾经安装旧版怎么办？

如果以前装过旧名称的 Skill，请在重新安装后通过所用 Agent 的 Skill 管理方式移除旧版本，避免出现两个同功能 Skill。**项目里已建立的记忆文件无需删除或重建。**

## 使用前需要知道

这是一个以 Prompt 为核心的 Agent Skill，**没有持续运行的录音或后台记录服务**。

要实现自动保存，AI 必须有项目文件夹的持久读写权限，并在新会话加载项目入口规则。Claude Code、Codex 等能读写本地文件的 Agent 较适合，具体设置取决于各平台。

**跨 AI 恢复依赖同一套项目文件。** 换了 AI 后需要让新的 Agent 访问这些文件。无法访问、也从未保存过的旧聊天，Skill 无法凭空恢复。

记忆保存在你授权的位置。个人学习记录和项目资料应注意隐私，未经许可不要上传到公开 GitHub 仓库。
