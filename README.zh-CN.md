# Adaptive Project Memory（中文说明）

这是一个以 Prompt 为核心的通用 Agent Skill。它让**当前模型自行设计、生成和维护项目的长期记忆文件**。你只需要描述真实目标、经历和偏好，不需要事先懂文件结构、开发架构或知识库设计。

真正的规则集中在 [`SKILL.md`](SKILL.md)。由模型在项目正式初始化时创建 `AGENTS.md`、`CLAUDE.md` 或当前 AI 软件支持的等效入口文件，并在其中明确规定**今后每轮有价值的交流都要及时保存项目记忆**。该入口文件还会说明从哪里读取进度、如何验证写入和怎样恢复下一次会话。它的具体内容由模型结合项目自行决定。

## 如何开始

**先聊天，正式开始时再初始化：** 正常 Brainstorming，决定后说：“使用 adaptive-project-memory，根据目前的讨论正式初始化这个项目，你自己设计文件。”这种方式依赖初始化时仍然能读取前文。

**想在讨论阶段就减少信息丢失，推荐这样做：** 一开始说：“使用 adaptive-project-memory 的 capture-only 模式，我们先讨论，你持续保存重要内容。等我说正式启动时再建立完整项目。”同时给 Agent 一个允许写入的持久文件夹。此时只建立轻量的临时记忆记录，尚不冻结项目设计。

**已经有旧项目：** 直接说：“检查这个项目现有的代码、文档、聊天摘要和状态，安全建立长期记忆系统。不要覆盖现有文件。”

**新会话继续：** 在同一项目目录打开支持自动读取入口文件的 Agent，让它读当前状态及相关资料，继续工作并及时更新记录。

## 中途加入已有项目

如果你已经学习几个月、开发到一半，或之前存在许多聊天记录，可以直接告诉 Agent：

“这个项目已经进行了很久。请使用 adaptive-project-memory，从你实际能够读取的历史资料恢复当前进度，建立长期记忆系统，然后从现在的进度继续。”

模型会先检查可访问的对话、笔记、测验、代码和其他资料，整理已完成工作与重要决策，标明证据来源和未恢复的内容。对于确实不可访问的旧聊天，它会说明限制，只在必要时请你补充相关记录。之后还可以增量补录，不必一次恢复全部历史，也不应把旧进度覆盖到最新状态。

## 安装

Claude Code：将整个 `adaptive-project-memory` 文件夹放到 `~/.claude/skills/` 或项目的 `.claude/skills/` 下。

Codex：将整个文件夹放到项目 `.agents/skills/` 下，具体以所用版本的发现规则为准。

其他工具可使用 `SKILL.md` 作为通用指令，但能否自动读取入口文件、跨会话写回同一个文件夹，取决于平台功能和权限。普通无文件访问能力的聊天工具无法真正实现自动持久化，只能生成需另存的记录。

## 三个重要事实

1. Skill 中的规则会指导模型进行判断，**不会把项目限定到固定模板**；模型可以随着项目演化调整文件结构。
2. 将持续写入要求写进项目入口文件，能帮助下一次会话继续执行规则，前提是 AI 软件确实自动加载该入口文件并有持久化写入权限。
3. 不能承诺 100% 零丢失。最重要的防范措施是及时写入、读回验证、保留详细历史、避免覆盖和做好备份。

在公共 GitHub 仓库发布此 Skill 本身通常没有私人项目内容。但用户项目中的学习记录、个人信息等应保存在私有位置，切勿未经授权上传。

运行结构测试：`python3 -m unittest discover -s tests -v`。测试可确保 Skill 文件格式和关键规则齐全，并不能替代真实模型、跨平台及长对话验证。
