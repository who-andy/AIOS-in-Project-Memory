# AIOS in Project Memory

**让 AI 在本地项目目录里自己创建长期记忆文件、持续记录进度，并在新对话或更换 AI 后快速恢复记忆，接着上次继续。**

你只需要正常聊天、学习或开发。AI 会自行判断哪些信息值得保存、该建什么文件、如何维护。**不用自己设计文件结构，也不用每次开启新 Session 都从头解释项目。**

## 一键安装

```bash
npx skills add who-andy/AIOS-in-Project-Memory
```

全局安装，供多个项目使用：

```bash
npx skills add who-andy/AIOS-in-Project-Memory -g
```

查看 CLI 是否识别到该 Skill：

```bash
npx skills add who-andy/AIOS-in-Project-Memory --list
```

安装使用开源 [Skills CLI](https://github.com/vercel-labs/skills)，需要 Node.js/npm 和兼容的 AI Agent。

### 更新已安装的 AIOS

先检查是否有更新：

```bash
npx skills check
```

如果之前**安装在项目内**，进入对应项目目录执行：

```bash
npx skills update aios-in-project-memory -p
```

如果之前是**全局安装**（使用了 `-g`），执行：

```bash
npx skills update aios-in-project-memory -g
```

**如果更新时报 `Failed to update`：** Skills CLI 的更新流程可能在内部重新安装时失败，却没有显示具体错误。可直接从 GitHub 重新安装最新版，绕过 `update` 流程：

```bash
# 全局安装的用户
npx skills@latest add who-andy/AIOS-in-Project-Memory --skill aios-in-project-memory -g -y

# 项目内安装的用户（先进入该项目目录）
npx skills@latest add who-andy/AIOS-in-Project-Memory --skill aios-in-project-memory -y
```

这只是重新安装 Skill，**不要删除原有项目记忆、PS 草稿或 AGENTS.md/CLAUDE.md**。如果直接安装也失败，请查看命令打印的实际报错，检查 Node.js 版本、GitHub 连接和安装范围。

更新后重新开启 Claude Code 或 Codex 会话，让 Agent 加载新版 Skill。**更新安装包不会直接改动已有项目记忆文件**；对于旧项目，首次需要在原项目中调用新版 AIOS，按需完成安全迁移，详见下文的[旧项目记忆自动迁移](#旧项目记忆自动迁移)。

## 它是怎么工作的？

1. **正常和 AI 聊天。** 先讨论项目想做什么、如何学习、软件要实现哪些功能。可以聊清楚后再正式启动记忆系统。
2. **AI 自动创建记忆文件。** 正式初始化时，AI 根据目前已有的讨论和资料，在**本地项目目录**自行建立入口规则、进度记录以及必要的其他文件。具体结构由 AI 决定。
3. **聊天过程中持续保存。** AI 通过生成的项目规则，在后续工作时及时记录重要决策、学习进度、错误、纠正和下一步。
4. **开启新对话，甚至更换 AI。** 只要新的 Agent 可以访问相同的项目目录并读取入口规则，它就能恢复相关记忆，从之前的进度继续。

例如，学习了几周之后，项目目录可能包含简短的入口说明、学习进度和详细笔记。但**这些文件由 AI 根据实际项目设计**，Skill 不会强制套用某种模板。

## 怎么开始？

**方式一：先讨论，准备好了再初始化**

> 我们已经讨论得差不多了。请使用 aios-in-project-memory，在当前本地项目目录中建立长期记忆系统。你自己决定需要哪些文件，以后持续维护。

**方式二：讨论期间就保存信息**

> 使用 aios-in-project-memory，一边和我讨论一边把有价值的信息记录到当前项目目录。暂时不用建立完整结构，等我说正式开始再初始化。

**方式三：已经学习或开发到一半**

> 这个项目我已经做了很久，之前还有好几个对话。请使用 aios-in-project-memory，从你实际能访问的旧对话和文件中恢复当前进度，在本地建立长期记忆，让我从现在的进度继续。

## 随着项目变化，自动调整复杂度

**只有一个目标，就保持简单。** AI 只创建当前真正需要的记忆记录；换一个聊天 Session，不会凭空多出一个子项目。

**以后出现多个目标，再按需扩展。** 比如大学申请逐渐涉及 PS、CV、活动素材。它们可以共享一套可信的背景事实，各自保留草稿、决策和进度。用户不用提前规划文件夹。

**目标完成或减少，还能再简化。** AI 可以归档已完成的任务，合并重复的活跃记录，减少新 Session 必须读取的内容；历史仍应可恢复。暂时没提某件事，不代表用户放弃它。更新共享事实也不会擅自改写其他文书。

整个原则是：**始终使用足以正确恢复项目进度的最简单结构。**

## 任意层级嵌套与动态共享记忆

一个项目可以继续包含子项目，子项目还能再包含子项目。**AIOS 根据实际任务关系决定需要几层目录，不设固定深度，也不要求用户提前规划。** 只有一个目标时，依然使用简单结构。

例如大学申请项目逐渐扩展为：

```text
Applications/
├── AGENTS.md              # 项目入口，按宿主需要创建
├── shared/                # 跨学校共用的真实经历、证据
│   └── activities.md
└── universities/
    ├── HKU/
    │   ├── shared/         # 只在港大范围共用的资料
    │   ├── PS/             # 港大 PS 专属要求、草稿、进度
    │   └── Interview/      # 港大面试专属要求、进度
    └── HKUST/
        ├── PS/
        └── Interview/
```

**目录只是示例，不是固定模板。** AI 也可以按文书类型、客户、产品或其他实际关系组织，并根据项目变化调整层级。需要独立管理的目标应当分开，不能把互相冲突的要求全部堆在根目录。

**共享信息也会动态更新。** 比如你准备港大面试时，需要一段原先只记录在港大 PS 笔记中的创业经历。AIOS 应在有权访问的相关文件中寻找证据，判断它是否为可信、可复用的事实，再将其引用或整理到适当的共享层，例如港大内部共享或整个申请项目共享。

但 PS 字数限制、某个专业的申请要求、尚未核实的叙事说法，不能因为被找到就自动变成所有学校共用的规则。跨任务复用前需要检查来源、适用范围和权限。新 Session 也应先识别当前目标，再按需读取相关层级。

旧项目如果文件已经混在根目录，**单纯更新 Skill 不会自动搬动旧文件**。应在原项目中让 AI 审计、备份、分类和安全迁移，并检查之前草稿有没有串用错误要求。

## Claude Code 和 Codex 都能用，不用学习「中控」系统

项目出现多个独立任务或任务依赖时，AIOS 会按需维护一份**精简、可核实的项目状态**，帮助不同 Session 找到各自的进度、阻塞事项和需要复核的共享资料。简单项目继续只保留必要的记忆，不会强制创建中控 Session、任务面板或额外文件夹。

对于更复杂的开发项目，AIOS 可以根据实际宿主识别可用的扩展：Claude Code 的 Hooks、Subagents、定时机制，以及 Codex 的多 Agent、Automations 等。**这些功能默认关闭，不需要用户额外配置才能使用基本记忆能力。**

如果你说「每天帮我检查项目进度」，AIOS 会先判断当前平台是否真正支持定时任务、是否有相应权限、执行环境能否访问项目文件。定时功能必须由实际宿主创建并确认，Skill 自身不会在后台常驻，也不会擅自安排耗费模型用量的周期任务。

技术细节放在 [项目状态协调](references/project-coordination.md) 和 [按需宿主适配](references/host-adapters.md) 两份参考说明中，普通使用无需阅读。

## v0.10.0：记忆治理（Memory Governance）

AIOS 现在更明确地区分**临时反馈、长期偏好、已核实事实和未经验证的解决方法**。比如「这段先保留」只适用于当前稿件，不应自动变成所有 PS 的写作规则；而明确的长期偏好可以在合适的范围内持续生效。

对于值得长期保留的规则，AIOS 在内部识别 `candidate`（候选）、`active`（当前适用）、`superseded/retired`（已被替代或停用），并与事实的**来源可信程度**分别处理。用户明确认可一条偏好，并不代表其提到的外部事实已经独立核实。

共享信息被纠正时，AIOS 应维护一处权威记录，保留原始依据与可恢复历史，提示受影响的子项目复核，不擅自修改其他交付物。曾经解决过的错误也可保存**触发环境、实测方法及不适用条件**，避免下次重复踩坑。

验证分三层，按实际需要执行：**保存成功 → 新 Session 实际读取 → 真实交付正确应用**。文件同步、Skill 安装或 AI 表示「我记得」不等于第三层已经通过。

**用户不需要学习新命令，也无需额外配置文件、规则登记表或中控 Agent。** 简单项目依然保持简单，只有出现重要反馈、冲突、规则迁移或交付验收需求时才深入检查。详细机制参见[记忆治理参考](references/memory-governance.md)和[行为测试场景](evals/memory-governance.md)。真实跨 Session 效果仍需在具体 Agent 环境下验证。

## 旧项目记忆自动迁移

**新版本真正被 Agent 加载后，AIOS 可以自动检测并安全升级旧项目的记忆结构。** 例如发现原来港大、港科的文件混放在根目录时，它会检查文件、制定精简迁移方案、备份、分类整理、修复引用并验证恢复情况。已经符合需求的项目不需要为了升级版本号而重组。

新项目的入口文件会保存类似 `AIOS memory policy: 0.10.0` 的标记，表示**已实际成功应用的项目记忆规则版本**。只有迁移经过验证，AI 才能更新标记。以后若能读取本机可信的新版本 Skill，入口规则会提醒 Agent 检查是否需要升级；如果读不到新版，项目仍可按现有规则继续使用。

**首次从旧版升级，需要主动加载一次新版 Skill。** 仅运行安装工具的更新命令，不会唤醒旧 Session，也无法确保旧版 `AGENTS.md` 或 `CLAUDE.md` 自己知道新规则。这是一项由 Agent 在实际运行中执行的迁移能力，没有后台常驻更新服务。

迁移只自动进行能验证且可回退的低风险变更。删除历史、覆盖无法恢复的文件、跨权限共享资料等高风险操作必须确认。不会自动把私人申请文件上传 GitHub。

在旧项目目录首次更新后，可以对 AI 说：

> 使用最新版 aios-in-project-memory，检查当前项目的旧记忆文件，自动完成安全、必要且可回退的结构迁移；保留原始资料和历史，验证成功后才更新项目记忆版本标记。

## 具体会保存什么？

AI 会尽量保存**能够帮助下一次对话准确继续**的重要内容，例如项目目标、当前进度、已验证成果、重要决策及原因、学习中的错误与纠正、待解决问题和下一步。

新 Session 优先读取精简的当前状态，需要时再检索详细历史，避免每次塞入整段旧聊天。对于尚未确认的想法，AI 应明确标注，避免把讨论中的猜测误记为最终决定。

项目已经进行到一半也可以使用。它支持从可访问的旧资料中逐步恢复历史，之后继续补录。

## 曾经安装旧版怎么办？

如果以前装过旧名称的 Skill，请在重新安装后通过所用 Agent 的 Skill 管理方式移除旧版本，避免出现两个同功能 Skill。**项目里已建立的记忆文件无需删除或重建。**

## 使用前需要知道

这是一个以 Prompt 为核心的 Agent Skill，**没有持续运行的录音或后台记录服务**。

要实现自动保存，AI 必须有项目文件夹的持久读写权限，并在新会话加载项目入口规则。Claude Code、Codex 等能读写本地文件的 Agent 较适合，具体设置取决于各平台。

**跨 AI 恢复依赖同一套项目文件。** 换了 AI 后需要让新的 Agent 访问这些文件。无法访问、也从未保存过的旧聊天，Skill 无法凭空恢复。

记忆保存在你授权的位置。个人学习记录和项目资料应注意隐私，未经许可不要上传到公开 GitHub 仓库。
